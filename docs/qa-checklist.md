# kubeport QA 체크리스트 — 라이브 데모 수동 점검

라이브 데모(https://kubeport.enzo.kr)를 **사람 손으로** 훑는 체크리스트다. 자동 테스트나 인계 이슈의 개별 검증이 이미 본 것을
다시 재는 게 아니라, **"처음 온 사람이 이 흐름을 따라가면 막히는 데가 있나"** 를 눈으로 본다. 흐름은 사용자(demo-user) →
관리자(demo-admin) → 공통 순이다.

> 로컬 kind 스택으로 같은 화면을 돌리는 절차(인증서·compose·kind·시드)는
> [docs/local-e2e.md §0](local-e2e.md#0-빠른-시작--어느-pc-에서든-권장-경로) 에 있고, 자동으로 도는 브라우저 시나리오는
> [§9c Playwright specs](local-e2e.md#9c-playwright-specs-what-pnpm-teste2e-runs-in-order) 다. 이 문서는 라이브 데모 기준이다 —
> 로컬 스택은 데모 구역이 `default` 라서 A3 의 구역은 `default` 로 열리고, A5 의 "`default` 로 바꾸면 거부" 는 `kube-system` 같은
> 다른 구역으로 확인한다. 라이브 데모 계정으로는 막혀 있는 흐름은 맨 아래 **D** 에 모았다.

## 0. 시작 전에

- [ ] `curl -s https://kubeport.enzo.kr/api/healthz` 의 `version` 을 결과 기록 첫 줄에 적는다.
- 계정·비밀번호는 랜딩(`/`)의 "데모 체험" 영역에 있다. 공통 비밀번호와 역할별 계정 카드에서 읽는다. **비밀번호는 회전되므로 화면에서 읽는다.**
  로그인 절차의 세부(프리필·로그아웃 확인)는 [.claude/skills/pr-review/references/demo-accounts.md](../.claude/skills/pr-review/references/demo-accounts.md).
- `demo` 구역은 **매일 06:00 KST 에 초기화**된다. 만든 릴리스·초안은 흐름 끝에 **직접 지운다**(리셋을 기다리지 않는다).
- 시드: 템플릿 3개(`web-app`·`nightly-job`·`app-with-config`), 릴리스 2개(`app-with-config-demo` 정상, `nightly-job-demo` 는
  **의도된 실패** — 존재하지 않는 이미지). #410 시드의 실패 릴리스는 UTC 5분 간격으로 실행하며 카탈로그 기본값은 매일 UTC 03:00이다.
  기존 시드는 이미지 배포만으로 바뀌지 않는다. 반영·리셋 확인은 [운영 runbook §5](oci-prod-runbook.md#데모-모드-운영-plan-13-2026-09-08-롤아웃-완료)를 따른다.
- **이미 알려진 정상 동작 — 결함으로 적지 않는다**
  - `app-with-config`·`nightly-job` 을 `demo` 에 배포하면 **409** 다(시드 릴리스가 같은 오브젝트를 쥐고 있다, #161). 배포 흐름은
    비어 있는 `web-app` 으로 한다.
  - 데모 계정은 **새 템플릿 생성**(설치가 `demo.allowTemplateCreate` 를 켜지 않았을 때)과 **버전 게시·deprecate·되돌리기가 403** 이다
    (#294). 기존 데모 템플릿의 초안 작성·미리보기는 된다.
- 브라우저 하나로 순서대로 한다: **사용자 → 로그아웃 → 관리자 → 로그아웃 → 공통.** 로그아웃은 우측 상단 계정 메뉴 → 로그아웃,
  끝나면 `/catalog` 를 다시 열어 로그인 화면으로 돌아왔는지 본다.

## A. 사용자 (demo-user) — "k8s 를 모르는 신입이 웹 서버 하나 띄우기"

### A1. 랜딩·로그인
- [ ] 로그인 없이 `/` — 무엇을 하는 서비스인지 한 문단으로 이해된다. "데모 체험" 영역에 공통 비밀번호와 역할별 계정·체험 버튼이 보이고, 이메일·비밀번호 전체를 선택해 복사할 수 있다(#413).
- [ ] 랜딩 비교 위젯(폼 ↔ YAML)에서 「환영 문구」 를 지운다 — 비운 동안 "비워 두면 기본값(Hello from kubeport)을 씁니다." 가 보이고,
      왼쪽 YAML 은 `value: "Hello from kubeport"`(빈 문자열 아님)다. 다시 쓰면 안내가 사라지고 YAML 이 그 값이 된다(#334, #341).
- [ ] 「웹 서버 버전」 선택지 맨 앞에 "선택 안 함 (기본값 사용)" 이 있고, 고르면 YAML 이미지가 기본값으로 남는다(#326).
- [ ] "사용자로 체험" → Dex 로그인 → `/catalog`. 상단 데모 배너에 "다음 초기화: 오전 06:00 UTC+9", 우측 상단에 사용자 계정,
      헤더 "에러 표시" 시작값 **간단히**, "색 테마" 시작값 **시스템 설정**.

### A2. 카탈로그
- [ ] 카드 3장 — 이름·설명·태그·버전만 보고 무엇을 만들어 주는지 알 수 있다.
- [ ] 검색에 `web` → `web-app` 만 남고, 지우면 3장이 돌아온다.
- [ ] "Kubernetes 용어로 보기" 스위치는 카탈로그가 아니라 **배포 폼 미리보기와 릴리스 화면**에 있다(A3·A4 에서 본다). 사용자는 **쉬운 용어**
      (구역·앱·설정·비밀값)로 시작하고, 켜면 Namespace·Deployment·ConfigMap·Secret 으로 바뀐다. 한 화면에서 바꾸면 두 화면에 함께 적용된다.

### A3. 배포 폼 — `web-app`
- [ ] 배포 이름이 자동으로 채워져 있고(`web-app-xxxx`), 구역 **`demo`**, 클러스터 `oci-a1`.
- [ ] 항목마다 `(?)` 도움말이 기술 용어 없이 "무엇을 정하는 값인지" 한두 문장으로 말한다.
- [ ] 오른쪽 미리보기에 만들어질 오브젝트 3개(설정·앱·내부 주소)와 "권한 확인 → 위 목록을 모두 만들 수 있습니다."
- [ ] 배포 이름에 대문자·공백·한글·하이픈 끝을 넣으면 칸 아래 빨간 안내가 즉시 뜨고 배포 버튼이 막힌다. 70자를 붙여 넣으면 63자에서 멈춘다.
- [ ] 「메모리 상한」(선택 항목 토글) — 선택된 `128Mi` 를 다시 누르면 아무것도 눌리지 않은 상태가 되고, 미리보기는 기본값 `128Mi` 를 쓴다.
      `256Mi` 를 누르면 그 값이 선택된다(#327).
- [ ] 「환영 문구」 를 비우면 "비워 두면 기본값(Hello from kubeport)을 씁니다." 가 보이고 미리보기의 값이 기본값이다. 공백만 넣으면 안내 없이 그대로 보낸다(#334).
- [ ] 「환영 문구」 를 `안녕하세요 kubeport`, 「동시에 띄울 개수」 를 2, 이름을 `hello-<이니셜>` 로 바꾸고 **배포하기** → 몇 초 안에
      릴리스 상세로 이동. 새 배포 뒤에는 "바뀐 설정을 적용했습니다" 안내가 **나오지 않는다.** 상태가 잠시 대기였다가 **정상**, 인스턴스 2/2.

### A4. 릴리스 상세
- [ ] 외부 접속 주소가 없는 릴리스에서 다음 행동 안내와 로그 링크가 보이고, 링크가 해당 릴리스의 로그 탭으로 연결된다(#411).
- [ ] 개요 — 인스턴스 표 2줄, 재시작 0. 상대시각("n초 전") 위에 마우스를 올리면 절대시각에 ` UTC+9` 가 붙는다.
- [ ] 로그 탭 — 두 파드 로그가 `[시각] [파드]` 접두어로 섞여 흐른다. "전체 인스턴스" 에서 한 파드만 고를 수 있다. "자동 스크롤" 을 끄고 올려도 튀지 않는다.
- [ ] (선택) 네트워크를 잠깐 끊었다 되돌린다 — 로그 줄이 중복·유실 없이 이어진다(#172).
- [ ] 헤더의 **"설정 바꾸기"** 링크로 업데이트 폼에 들어간다(#354). 화면 제목이 **`'hello-<이니셜>' 설정 바꾸기`**, 제출 버튼이
      **`바뀐 설정 적용`** 이다(#359). 현재 값이 채워져 있다.
- [ ] 「환영 문구」 를 **비우고** "바뀐 설정 적용" → 상세로 돌아오며 헤더 아래 초록 안내 "바뀐 설정을 적용했습니다. 새 설정으로 다시 뜨는 동안
      상태가 잠시 바뀔 수 있습니다." 가 보인다. 주소창에 `applied` 가 남지 않고, 새로고침·뒤로 가기로 다시 뜨지 않으며, "닫기" 로 닫힌다(#367).
      적용된 값은 기본값 `Hello from kubeport` 다(#334). 개요·로그에는 그 값이 보이지 않으므로, DevTools 콘솔에서
      `await (await fetch('/api/v1/releases/<id>')).json()` 을 열어 `values_json` 에 「환영 문구」 키가 **없고** `rendered_yaml` 의
      `WELCOME_MESSAGE` 가 `Hello from kubeport` 인지 본다. ("설정 바꾸기" 를 다시 열면 저장값에 키가 없으니 그 칸은 기본값으로 채워져 보인다.)

### A5. 실패 릴리스와 에러 표시 단계
- [ ] 리셋 직후에는 다음 UTC 5분 경계와 이미지 다운로드 시도까지 기다린다. 실행 상한 240초·재시도 0회·성공/실패 이력 각 1개이며, 실패 설명과 최소 두 주기 동안 잡·파드 수가 계속 증가하지 않는지 확인한다(#410). 클러스터·레지스트리 지연과 시드 미반영은 별도로 기록한다.
- [ ] 릴리스 목록 → `nightly-job-demo` — "무슨 일이 있었나요" 패널이 **k8s 용어 없이** 이미지를 받아오지 못했다고 설명하고 다음 행동을 말한다.
      `ImagePullBackOff` 같은 원문은 용어 스위치를 켰을 때만 보인다.
- [ ] `app-with-config` 배포 폼 → 「API 키」 에 `x` → 배포하기 → 409. 헤더 "에러 표시" 를 바꿔 가며 같은 거절을 본다(#6).
  - [ ] **간단히** — 번역된 문장 하나와 문의용 복사 블록(요청 ID·시각·상태 `409 resource-conflict`·템플릿·클러스터·구역·배포 이름)만.
        서버 원문·구조화 필드는 없다.
  - [ ] **자세히** — 접힌 "자세히 보기" 한 칸이 더해지고, 펼치면 종류·서버 메시지·구조화 필드(`conflicts`)가 들어 있다.
  - [ ] **원문** — 메시지가 모두 펼쳐지지만 JSON 봉투(`{"type":…`)는 없다. 새로고침해도 선택이 유지된다. 끝나면 **간단히**로 되돌린다.
  - [ ] 409 문구가 **어느 릴리스**(`app-with-config-demo`) 때문인지, 이름을 바꿔도 소용없다는 것, 다른 구역에 배포하거나 그 릴리스를 지우라는
        것을 말한다. 아무것도 만들어지지 않았다(목록 확인).
- [ ] `app-with-config` 배포 폼에서 「API 키」 를 채웠다가 지운다 — "필수 항목입니다.", 미리보기가 비고 "필수 항목을 채우고 표시된 오류를 고치면
      미리보기가 나옵니다." / "미리보기가 나오면 만들 수 있는지 확인합니다." 가 보인다. 다시 채우면 돌아온다(#331, #322).
- [ ] 배포 폼 구역을 `default` 로 바꾸면 권한 패널이 거부로 바뀌고, 거부 문장이 `demo` 로 배포하라는 방향을 말한다. 배포 버튼은 막힌다.
- [ ] 구역을 `demo`로 되돌리면 권한을 다시 확인하고 허용 상태로 복구된다. 데모 구역 안에서 거부된 경우에는 일반 관리자 문의 안내를 유지한다(#410).
- [ ] **데모 한도**(#353) — 설치가 이미지 허용 목록(`demo.policy.allowedImagePrefixes`)을 켰다면, `nightly-job` 배포 폼 「이미지」 에 목록 밖
      이미지(예: `docker.io/library/alpine:3`)를 넣는다. 미리보기가 "데모 계정으로는 '…' 이미지를 쓸 수 없습니다." 와 "'이미지' 에 다른 이미지를
      넣으세요." 를 보인다. 목록 밖 이미지를 넣어도 미리보기가 거절하지 않으면 ❌ 로 적지 말고 "이미지 한도: 거절 없음 — 설치값 확인 필요"
      로 남긴다(허용 목록이 비어 있는 설치는 모든 이미지를 허용하고, 차트 기본값이 빈 목록이다. 라이브 설치값은 PM 이 `helm get values` 로 확인한다).
      시드 템플릿의 다른 한도 값은 폼에 노출되지 않아 여기서 볼 수 없다.

### A6. 정리
- [ ] `hello-<이니셜>` 상세 → 삭제. 확인 창 문구가 `'hello-<이니셜>' 을(를) 클러스터에서 내리고 목록에서 지웁니다. 되돌릴 수 없습니다. 계속할까요?`
      — 저장소가 없는 템플릿이라 **저장소 줄이 없다**(#347). 삭제 후 목록에서 사라진다.
- [ ] 계정 메뉴 → 로그아웃 → `/catalog` 재방문 → 로그인 화면(`/?next=/catalog`).

## B. 관리자 (demo-admin) — "템플릿 작성자가 새 템플릿을 설계해 보기"

> 데모 계정은 **새 템플릿을 저장할 수 없고 게시할 수 없다.** 새 템플릿은 설계·미리보기까지만 보고, 저장 시 거절 문구를 확인한다.
> 기존 템플릿의 초안을 저장해 봤다면 끝에 직접 지운다.

### B1. 로그인·목록
- [ ] "관리자로 체험" → 사이드바에 **템플릿·릴리스·팀**, "에러 표시" 시작값 **자세히**(A 에서 바꾼 값이 쿠키로 남아 있으면 그 값).
- [ ] `/templates` — 시드 3개가 표 한 줄씩(표시 이름·현재 버전 `v1`·설명)으로 보이고, 이름을 누르면 상세로 간다. 초안 여부는 상세의 버전 목록에서 본다.

### B2. 템플릿 상세·버전 관리
- [ ] `web-app` 상세 → 게시 버전의 **사용 중단**(deprecate) → 403 과 "데모 계정은 버전을 게시하거나 게시 상태를 바꿀 수 없습니다. 초안 작성과
      미리보기는 그대로 쓸 수 있습니다." 버전 상태는 그대로다(#294). 초안이 있으면 **게시** 도 같은 문구.
- [ ] 새 버전(초안) 편집 화면이 이름 **잠금** 상태로 열리고, 이름 규칙 안내는 달리지 않는다(#375).

### B3. 새 템플릿 — UI 모드
- [ ] 편집 전에 데모의 새 템플릿 저장·게시 제한 안내가 보인다(#411).
- [ ] `+ 새 템플릿` 첫 화면 — 미리보기 두 탭(YAML·사용자 폼)이 모두 "리소스를 추가하면 여기에 미리보기가 나옵니다." 뿐이고 오류·요청 ID 가 없다(#332).
- [ ] 이름 칸에 `My/App`·`web-` 를 넣으면 칸 아래 "이름은 영문자·숫자·하이픈·점으로 63자까지 쓰고, 영문자나 숫자로 시작하고 끝나야 합니다(점 바로
      뒤도 영문자나 숫자). …" 가 뜨고 저장 버튼 옆에 이유가 보이며 저장이 막힌다. `hello-cm` 처럼 맞는 이름이면 사라진다(#375).
- [ ] kind 선택기의 GroupVersion 목록 — 데모 계정은 `v1`·`apps/v1`·`batch/v1`·`authorization.k8s.io/v1` 만 보인다(#283).
- [ ] ConfigMap 추가 → 트리에서 `data` 필드를 노출로, 인스펙터에서 라벨 `인사말`·기본값 `hi`. YAML 탭 `ui-spec.yaml` 에 그 필드, 사용자 폼 탭에 "인사말" 칸.
- [ ] 트리의 리소스 이름(`metadata.name`)을 **비운다** — 미리보기가 400 을 한 문장으로 보이고 복사 블록에 요청 ID 가 있다. 다시 채우면 복구된다(#339).
- [ ] "한 네임스페이스에 여러 번 배포 허용" 체크박스의 도움말을 읽는다 — 관리자가 이해할 문장인가. 켜면 `ui-spec.yaml` 에 `instances: multiple`,
      끄면 사라진다(#190).
- [ ] 미저장 표시 — 편집하면 "저장하지 않은 변경 사항이 있습니다" 가 켜지고, 되돌리면 꺼진다(#274). 켠 채 사이드바로 떠나면 확인 창이 뜬다(#146).
- [ ] **저장**을 눌러 본다(선택) — "데모 계정은 이 설치에서 새 템플릿을 만들 수 없습니다. 기존 데모 템플릿에 새 버전을 추가하는 것은 가능합니다. 편집 내용은
      그대로 남아 있습니다." 가 보이고 편집 내용이 남아 있다.

### B4. 새 템플릿 — YAML 모드
- [ ] 기존 템플릿 버전의 YAML 편집 화면에서 템플릿 이름·`vN`·초안/게시/사용 중단 상태가 보인다. UI/YAML 모드를 바꿔도 편집 대상이 유지되고 좁은 화면에서 긴 이름이 줄바꿈된다(#408).
- [ ] YAML 모드 — 예시 resources + ui-spec 가 채워져 있고, 아래 사용자 폼 미리보기가 그려진다.
- [ ] 문법 오류(`replicas: [1, 2`) — 에디터 오류 마커와 하단 "오류 1건을 고쳐야 저장할 수 있습니다. resources.yaml N행: …"(#181).
- [ ] ui-spec 에 없는 경로·스키마 위반(`replicas: "many"`) — 경고 마커와 "오류 0건, 경고 N건" 목록. 경고는 저장을 막지 않는다.
- [ ] ui-spec 에 필드를 넣어 사용자 폼 미리보기의 위젯을 본다.
  - [ ] `required: true` enum(값 4개 이하, 각 값 24자 이하 — 더 많거나 길면 Select 로 그려진다) → **라디오 그룹**. Tab 은 그룹당 한 번, 화살표·Space·Enter 로 체크되고 Enter 가 제출하지 않는다. 다시 눌러도 해제되지 않는다(#325).
  - [ ] 값 5개 이상인 선택 enum → Select 맨 앞에 "선택 안 함 (기본값 사용)"(기본값 없으면 "선택 안 함")(#326).
  - [ ] min/max 없는 `integer` + `default: 3` → 칸을 지우고 `5` 를 치면 `35` 가 아니라 `5`(#321).
  - [ ] `Secret[s].stringData.K` 경로의 `type: string`, `default: "sekret"` → 칸에 기본값이 채워져 있다. 칸을 **비우면** "비워 두면 기본값을 씁니다."
        가 뜨고, 이 문구는 기본값을 드러내지 않는다(#334). 참고: 에디터 미리보기 폼은 처음 그려질 때의 값을 유지하므로, 필드를 먼저 만들고 나중에
        `default` 를 적었다면 칸이 비어 보일 수 있다 — 결함으로 적지 않는다. 확인하려면 ui-spec 을 잠깐 `fields: []` 로 비워 미리보기 폼을
        내렸다가 되돌린다(다시 그려지며 기본값이 채워진다).
- [ ] 저장하지 않고 사이드바로 떠난다(확인 → 나가기).

### B5. 릴리스·팀
- [ ] 릴리스 목록 — 데모 관리자에게는 **데모 계정이 만든 릴리스**(시드 2개와 A 에서 만든 것)가 보이고 실사용자의 릴리스는 보이지 않는다. 비정상만
      칩으로 표시된다. (데모가 아닌 관리자는 모든 릴리스를 본다.)
- [ ] `nightly-job-demo` 상세 — 강제 삭제 버튼은 **보이지 않는다**(stale 이 아니라 error 라서).
- [ ] `app-with-config-demo` 의 "설정 바꾸기" — 「API 키」 가 입력칸이 아니라 "기존 값을 유지합니다. 보안상 값은 보여 주지 않아요." 와 "새 값 입력"
      버튼으로 보이고, 화면·DOM 어디에도 `<redacted>` 가 없다(#310, #196). 제출하지 않는다.
- [ ] `/admin/teams` — 팀 목록이 뜨고, 데모 계정이 바꿀 수 없는 조작은 그렇게 말한다. 멤버를 바꾸지 않는다.
- [ ] 데모 관리자에게 팀 생성 제한 안내가 보이고 새 팀 입력·버튼이 비활성화되어 있다(#411).

### B6. 정리
- [ ] 저장해 본 초안이 있으면 상세에서 초안을 삭제한다. 로그아웃 → `/catalog` 재방문으로 확인한다.

## D. 로컬 스택에서만 볼 수 있는 것 (라이브 데모 계정으로는 403)

라이브 데모 계정은 게시·팀 관리·클러스터 등록이 막혀 있다(#294, `demo.allowTemplateCreate: false`). 아래는
[local-e2e.md §0](local-e2e.md#0-빠른-시작--어느-pc-에서든-권장-경로) 스택에서 `admin@example.com`(관리자)과 `alice@example.com`(일반
사용자)으로 본다(`deploy/docker/dex.yaml` 의 정적 계정).

- [ ] **버전 고정과 버전 옮기기** — 템플릿 v1 로 릴리스를 만든 뒤 v2 를 게시한다. 기존 릴리스의 상세는 여전히 v1 이다. 상세에는 "새 버전이 있다"
      배지가 **없으므로**, `/catalog/<템플릿>/versions/2/deploy?updateReleaseId=<릴리스 id>` 로 들어간다 — 제목이 "v2 로 업데이트" 이고 현재 값이
      채워져 있으며, Secret 값은 다시 입력해야 한다. 적용하면 릴리스 버전이 2 가 된다. 헤더의 "설정 바꾸기" 는 **같은 버전**의 값 바꾸기다.
- [ ] **초안 가시성** — 팀 밖 일반 사용자에게는 v2 초안이 버전 목록에 없고, 한 번도 게시하지 않은 템플릿은 `/catalog`·`/templates` 에 보이지 않는다.
      같은 팀 viewer 에게는 `/templates` 목록과 버전 목록에서 초안이 보이지만 편집·삭제는 거절된다. `/catalog` 는 역할과 무관하게 **게시된 템플릿만**
      보인다.
- [ ] **팀 멤버** — `/admin/teams` 에서 팀 생성, 멤버 추가(한 번 로그인한 이메일만), 역할 editor ↔ viewer 변경, 멤버 제거. 이미 있는 팀 이름으로 만들면
      거절된다.
- [ ] **팀 폼 오류·재전송** — 중복 팀 이름 등 서버가 거부하는 입력을 제출하면 오류 문구와 입력값이 남는다. 멤버 추가 오류에서도 이메일·선택 역할이 유지된다. 성공 후 폼은 초기화되고, 응답 대기 중에는 제출 버튼이 비활성화된다. 이 항목은 변경이 허용된 로컬 계정으로 수행한다.
- [ ] **deprecate** — 게시 버전을 사용 중단하면 카탈로그에서 배포할 수 없고, 이미 배포된 릴리스는 그대로다. 되돌리면 다시 배포할 수 있다.
- [ ] **멀티 클러스터** — 두 번째 클러스터를 등록하면 배포 폼에 클러스터 선택이 생기고, 바꾸면 권한 확인을 다시 한다. 릴리스 상세에 클러스터 이름이 보인다.
- [ ] **세션·백엔드** — 세션 쿠키를 지우면 로그인 화면으로 가고, 백엔드를 내리면 흰 화면 대신 오류 화면이 뜬다.

알려진 한계(결함으로 적지 않는다): 클러스터 삭제 API 가 없다(`DELETE /v1/clusters` 미구현) — 등록 해제는 DB 에서 직접 한다.
